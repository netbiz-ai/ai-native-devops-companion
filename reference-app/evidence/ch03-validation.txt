CONTROLLED FAILURE

APP_PORT=not-a-port python3 src/app.py
  ValueError: APP_PORT must be an integer
Raised from Settings.from_environment() at src/app.py:90, reached from main()
at line 206 - before any bind. The failure is a refusal to start, not a
partially started server on an unintended port, which is the behavior
docs/engineering-standards.md requires.

Observed separately: the printed form of this same step, APP_PORT=not-a-port
python3 -m src.app, also exits nonzero, but with
ModuleNotFoundError: No module named 'telemetry'. It is the wrong failure for
the right-looking exit status, so exit status alone would not have proved the
port validation works.

LIMITATION

These checks prove the contract on one machine, against a loopback listener,
started by hand. They prove nothing about the service under concurrency, behind
a proxy, in a container, or on a port it does not control. Chapter 4 takes up
container behavior; nothing here is evidence about it.
